## 2. ログインと管理画面

1. 本番サイトを開き、Googleアカウントでログインします。
2. 初回はプロフィール登録を完了します。
3. 管理メニューから「管理ダッシュボード」を開きます。直接開く場合は、本番サイトURLの末尾に `/admin` を付けます。
4. Administratorで管理メニューが出ない場合は、モード切り替えで「Administratorモードへ」を選びます。

ログインには大学メール（`@edu.teu.ac.jp`）など、システムで許可されているアカウントを使用します。個人Gmailの利用条件は矢内までお問い合わせください。メールアドレスの許可設定だけでは管理権限は付きません。

### 権限の基本

この引き継ぎ書は、Administrator・Supervisor・PA長（PA Leader）・照明長（Lighting Leader）・会計（Treasurer）が閲覧できます。会計の役職だけでは、イベント・ユーザー・お知らせなどの管理権限は付きません。

サイトの公開中に、ログインとプロフィール登録を完了した状態で閲覧できます。クローズ中は共通のサイト制限が優先され、Administrator・Supervisor以外は閲覧できません。PA長・照明長は、役職名の表示だけでなく、それぞれPA Leader・Lighting Leaderのロールが設定されている必要があります。

| ロール・役職 | 主な扱い |
| --- | --- |
| Administrator | 管理操作を行うロール。一般ユーザーとして確認するGeneralモードへの切り替えも可能 |
| Supervisor | イベント・ユーザー・在籍・お知らせ・サイト設定などの日常管理が可能 |
| PA Leader / Lighting Leader | 管理ダッシュボードの一部、お知らせ管理、ユーザーの担当設定などを利用可能 |
| Part Leader | このロール単独では管理ダッシュボードにアクセス不可 |
| Web幹事（Web Secretary） | 更新履歴の管理が可能。役職だけで日常管理全般の権限が付くわけではない |

画面ごとに利用できる機能が異なります。特に更新履歴の編集はAdministratorまたはWeb幹事が対象です。

**Administratorロールはユーザー管理画面から付与・解除できません。** 後任へのAdministrator付与が必要な場合は、矢内（[shirone.astral@gmail.com](mailto:shirone.astral@gmail.com)）までご連絡ください。

## 4. 日常の管理手順

### イベントを開催するとき

1. 「イベント管理」でイベントを作成し、名称・開催日時・会場などを登録します。
2. イベント詳細でレパ表の締切日時などを設定し、保存します。
3. 部員へイベントと提出期限を案内します。
4. レパ表の提出状況を確認します。「下書き」と「提出済み」を区別し、未提出のバンドへ確認します。
5. タイムテーブルを編集・保存し、内容を確認して仮確定します。仮確定するとシフト作成が利用できるようになります。
6. PA・照明担当とスタッフ配置を確認し、準備ができたらタイムテーブルを公開します。
7. 利用者向けイベント画面でも、日時・レパ表・タイムテーブルの表示を確認します。

「保存」「仮確定」「公開」は別の操作です。保存しただけで全員に公開されるとは限りません。また、「レパ表提出の手動締切」を有効にすると提出できなくなるため、追加提出を受け付ける際は設定を確認してください。

### お知らせを掲載するとき

1. 「お知らせ管理」でタイトル・本文・カテゴリを入力します。
2. 必要に応じて画像・添付リンクを設定します。
3. 下書きで内容を確認し、公開状態にして保存します。
4. 重要な案内は固定表示を設定します。
5. ホーム・お知らせ一覧で掲載内容とリンクを確認します。案内の終了後は固定表示を見直します。

### ユーザー・担当者を変更するとき

1. 「ユーザー管理」で対象者を検索し、本人であることを確認します。
2. 必要なロール・役職・PA／照明などの担当を設定して保存します。
3. 変更後の内容を再確認し、本人にも利用できる画面を確認してもらいます。

「部長」「Web幹事」「合宿幹事」などの役職と、操作権限を決めるロールは別項目です。合宿幹事の設定だけでは管理権限は付きません。

### 卒業・退部・休眠・復帰を扱うとき

本番で在籍管理の初期設定が完了している場合に使用します。

1. 「ユーザー管理」の「在籍・アカウント管理」を開きます。
2. 対象者と現在の状態を確認します。
3. 変更理由を入力し、卒業・退部・休眠などの状態へ変更します。
4. 復帰させる場合は「在籍中」に戻し、必要なロール・役職を改めて設定します。

卒業・退部・休眠では利用を停止しますが、既存バンドの名前・所属履歴は保持します。復帰後は元のGoogleアカウントで再ログインが必要で、以前の管理権限・役職は自動では戻りません。自分自身の停止・復帰はできません。

自動休眠は最終利用から暦上の6か月が基準です。管理画面に事前警告が出るため、定期的に対象者を確認してください。本人への自動メール通知はありません。詳細は[在籍・アカウント管理](account-lifecycle.md)を参照してください。

卒業や退部の処理には、履歴を残す在籍状態の変更を使います。「アカウント削除」は別の操作で、取り消せないため、削除が必要な場合は、事前に矢内までご相談ください。

## 6. 困ったとき

**技術的な問題が起きた場合は、矢内（[shirone.astral@gmail.com](mailto:shirone.astral@gmail.com)）までご連絡ください。** ログインできない、エラーが出る、画面が正常に表示されないなど、下記の基本確認で解決しない場合もこちらへお問い合わせください。システムの修正や設定変更は矢内が対応します。

| 症状 | 最初に確認すること |
| --- | --- |
| ログインできない | 使用中のGoogleアカウント、許可メール、在籍状態を確認。通信が正常なら再ログインを試す |
| 管理メニューが出ない | ロールと、Administratorの場合はGeneralモードになっていないか確認 |
| イベント・タイムテーブルが見えない | 対象イベント、保存結果、公開設定を確認 |
| レパ表を提出できない | 締切日時と「レパ表提出の手動締切」を確認 |
| サイトがクローズと表示される | 管理者が「サイト設定」の公開状態を確認 |
| 在籍管理で初期設定エラーが出る | 矢内まで連絡。初期設定は矢内が対応します |
| 保存できない・一覧が出ない | エラー文と発生時刻を記録し、再読み込み。改善しなければ矢内まで連絡 |
| 別の管理者による変更を知らせるエラーが出る | 再読み込みして最新状態を確認し、必要な変更をやり直す |

連絡時は「発生日時（日本時間）・画面URL・操作内容・エラー文・影響する人数」を伝えます。スクリーンショットを添付する場合は、学籍番号などの個人情報を必要以上に含めないようにします。

一時的に利用を止める必要がある場合は、「サイト設定」から「クローズする」を選びます。クローズ中も管理者は確認できます。対応後は「公開する」に戻し、一般ユーザー側でも表示を確認してください。この操作は画面の利用制御であり、漏えいなどの事故が疑われる場合も、速やかに矢内までご連絡ください。
